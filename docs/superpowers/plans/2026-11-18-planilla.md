# Menú, combos y horarios desde Google Sheets — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** que porciones, combos y horarios salgan de la planilla de Google y la web se actualice sola (≤ 5 min).

**Architecture:** el servidor lee cada pestaña como CSV (`gviz/tq?tqx=out:csv&sheet=<pestaña>`) dentro de una función
`"use cache"` con `cacheLife` de 5 min, la parsea y valida con funciones puras (testeadas con `node --test`), y pasa los
datos a las secciones como props. Los horarios llegan al cliente por un contexto; el cálculo de abierto/cerrado sigue en
el navegador. Respaldo: última lectura buena en memoria → datos de `content/*.ts`.

**Tech Stack:** Next 16.4 (`cacheComponents`), React 19.3, TypeScript, `node --test` (Node 22, type stripping nativo).

**Spec:** `docs/superpowers/specs/2026-11-18-planilla-design.md`

## Global Constraints

- Caché: `cacheLife({ stale: 300, revalidate: 300, expire: 86400 })`. Ante error de lectura: `cacheLife({ stale: 300, revalidate: 60, expire: 3600 })`.

## Review Focus

1. Encabezados con mayúsculas/acentos/espacios distintos ("descripcion", " Precio ") → se leen igual. (Test en Task 1.)
2. Celdas con comas, comillas o saltos de línea dentro de una descripción → CSV bien parseado. (Test en Task 1.)
3. Turno que cruza medianoche (20:00–01:00) consultado a las 00:30 del día siguiente → abierto. (Test en Task 2.)
4. Fecha especial que termina hoy / empieza mañana → hoy y mañana resueltos bien, aviso visible. (Test en Task 2.)
5. Carrito guardado con una porción que se apagó o cambió de precio → se quita / se actualiza con aviso. (Test manual en Task 5.)

  - `parseFechasEspeciales`: `hasta` vacío = `desde`; `desde` inválido → fila omitida; sin horas → `turnos: []`; `hasta < desde` → fila omitida.

### Task 2: Lógica de horarios con fechas especiales y medianoche (pura)

**Files:**
- Modify: `lib/horario.ts` (deja de importar `content/*`), `content/horarios.ts` (pasa a ser respaldo con forma `Horario`)
- Test: `tests/horario.test.ts`

**Interfaces — Consumes:** `Horario`, `Turno`, `HorarioSemanal` (Task 1). **Produces:**
- `ahoraEnArgentina(fecha?: Date): { dia: number; minutos: number; fechaISO: string }`
- `turnosDe(horario: Horario, fechaISO: string, dia: number): { turnos: Turno[]; especial?: FechaEspecial }`
- `type Estado = { abierto: boolean; detalle: string; aviso?: string }`
- `estadoActual(horario: Horario, fecha?: Date): Estado`
- `agruparHorarios(semanal: HorarioSemanal): { dias: string; turnos: string[]; diasNum: number[] }[]`
- `avisoVigente(horario: Horario, fecha?: Date): string | null` (aviso de una fecha especial activa hoy o que empieza en ≤ 7 días)

- [ ] **Step 1: Tests** (fechas construidas como `new Date("2026-11-17T12:00:00-03:00")`, martes):
  - semanal estándar (mar–dom 11:45–16:30 y 20:00–23:45, lunes cerrado): martes 12:00 → `{abierto:true, detalle:"Cierra en 4 h 30 min"}`; martes 17:00 → `"Abrimos hoy a las 20:00"`; lunes 12:00 → `"Abrimos mañana a las 11:45"`; domingo 23:50 → `"Abrimos el martes a las 11:45"`.
  - turno 20:00–01:00 el martes: miércoles 00:30 → abierto, `"Cierra en 30 min"`; martes 23:00 → `"Cierra en 2 h"`.
  - especial `{desde:"2026-11-17", hasta:"2026-11-20", turnos:[], aviso:"Vacaciones"}`: martes 12:00 → `{abierto:false, aviso:"Vacaciones", detalle:"Abrimos el sábado a las 11:45"}`.
  - especial de un día con turno 18:00–22:00 el martes: martes 12:00 → `"Abrimos hoy a las 18:00"`; martes 19:00 → abierto.
  - `avisoVigente`: especial que empieza en 5 días → su aviso; en 9 días → null; terminada ayer → null.
  - `agruparHorarios`(estándar) → `[{dias:"Martes a domingo", turnos:["11:45 a 16:30","20:00 a 23:45"], diasNum:[2,3,4,5,6,0]}, {dias:"Lunes", turnos:["Cerrado"], diasNum:[1]}]`; lunes a viernes iguales + sáb y dom cerrados → `"Lunes a viernes"` y `"Sábado y domingo"`; días no consecutivos con mismos turnos van en grupos separados.
- [ ] **Step 2:** `npm test` → FAIL.
- [ ] **Step 3:** Implementar. Orden de la semana para agrupar: lunes→domingo. Un turno con `cierra <= abre` cruza medianoche: cubre `[abre, 24:00)` de su día y `[00:00, cierra)` del día siguiente. El "próximo turno" busca hasta 14 días adelante usando `turnosDe` (respeta especiales).
- [ ] **Step 4:** `npm test` → PASS.
